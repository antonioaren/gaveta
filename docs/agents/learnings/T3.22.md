# T3.22 learnings

- `app.css` loads after `shell-chrome.css`; explorer/connections overrides that must win belong in `app.css`, not only shell-chrome.
- Note read layout polish lives in `packages/core/src/theme/theme-content.css`; re-copy `DEFAULT_THEME_CSS` to every `fixtures/**/.gaveta/theme.css`, `examples/demo-vault/.gaveta/theme.css`, and refresh `examples/demo-vault/.gaveta/config.json` theme hash when content changes.
- Visual editor Save/Cancel test ids stay on header `Button`s via `VisualNoteEditor` `forwardRef` + `onSavingChange`; do not rely on the inner toolbar (removed by default).
- Dark screenshots must set `gaveta.themePreference` and reload (or use the theme menu). Setting only `document.documentElement.dataset.theme` darkens the shell but leaves the render iframe light because `postThemeToRenderIframe` follows React `resolved`, not the DOM override.
- After syncing `examples/demo-vault/.gaveta/theme.css`, update `config.json` `assets['.gaveta/theme.css']`; `tests/demo-vault-config-assets.test.ts` guards every `assets` entry (on-disk bytes or bundled fallback for gitignored mermaid files).
