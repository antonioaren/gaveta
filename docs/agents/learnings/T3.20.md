# T3.20 learnings

- Split vault theme into `design-tokens.css` + `theme-content.css`; `theme.ts` concatenates for `DEFAULT_THEME_CSS`. Avoid `@import` inside shipped theme (theme tests forbid it). Comments must not contain the substring `@import`.
- WCAG matrix in `theme.test.ts` treats every `--color-*` in `:root` as a token; extra tokens like `--color-accent-brand` break the known-token list. Shell-only colors belong in `app.css`, not `design-tokens.css`.
- `--color-accent` in tokens must pass 4.5:1 on all surfaces; Pedro’s `#6366f1` fill lives in `--shell-accent-fill` in `app.css`. Link/focus tokens use darker indigo in shared tokens.
- Vite resolves CSS `@import` from `apps/web/src/styles/app.css` with **four** `../` segments to reach `packages/core`.
- Note iframe theme: `render-bridge.js` listens for `gaveta:theme`; shell posts on load and when preference changes. Vault notes keep system font stack (no `url()` in theme CSS per tests); Geist is shell-only via `@fontsource`.
- Context menu / tree indent: position with `--menu-top` / `--menu-left` via ref `setProperty`; explorer depth uses `--depth-N` classes (no `style={{}}`).
- Prettier formats generated `.gaveta/theme.css` copies; re-sync from `DEFAULT_THEME_CSS` after formatting sources, then update `examples/demo-vault/.gaveta/config.json` asset hash and `fixtures/src/generate.test.ts` GOLDEN when theme bytes change.
- Add previous default theme SHA to `SHIPPED_VAULT_ASSET_HASHES` when replacing the default palette so `upgradeVaultAssets` still upgrades untouched vaults.
