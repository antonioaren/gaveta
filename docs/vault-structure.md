# Vault structure

A **vault** is a directory tree of HTML notes plus a **`.gaveta/`** metadata folder.

## Layout

```text
my-vault/
├── .gaveta/
│   ├── config.json      # vault settings (remote allowlist, rel policy, asset versions)
│   ├── theme.css        # default theme (upgraded by gaveta update when untouched)
│   ├── index.sqlite     # search index (regenerated by reindex)
│   └── templates/       # optional per-type new-note templates
├── welcome.html         # example note at vault root
└── projects/
    └── roadmap.html
```

## Note files

Each note is a full HTML document:

- **`<title>`** — display title; drives slug filename  
- **`gaveta:id`** — ULID (stable identity)  
- **`gaveta:type`** — `doc`, `slides`, `todo`, `dashboard`, `design`, `artifact`, …  
- Optional: **`gaveta:tags`**, **`gaveta:aliases`**, **`gaveta:created`**, **`gaveta:updated`**  
- **`<link rel="stylesheet">`** — relative path to **`.gaveta/theme.css`** (CLI maintains depth)

Authoring rules (elements, components, security) are defined in the contract — run **`gaveta guide`**.

## Links

- **Wikilinks** — `[[Note Title]]` in HTML text  
- **Canonical links** — `<a href="…" data-g-to="…">` after normalization  
- **Pending links** — point at titles with no note yet; promoted when a matching note is created  

## Discovery

The CLI locates a vault by:

1. **`--vault`** argument  
2. **`GAVETA_VAULT`** environment variable  
3. Walking up from the current working directory for **`.gaveta/config.json`**

## Init and adopt

- **`gaveta init [dir]`** — creates **`.gaveta/`**, default theme, optional agent instruction files  
- **`gaveta adopt <file>`** — ingests external HTML (Claude exports, etc.)
